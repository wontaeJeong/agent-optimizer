# 터미널·리포트 한영 지원 설계

## 목적과 범위

개발 명령(`make`, `scripts/bootstrap.sh`, `scripts/dev.py`, 번호 메뉴)과 사용자 명령(`agent-opt`, TUI)의 사람이 읽는 문구를 **한국어 기본, 영어 선택**으로 제공한다. 같은 선택을 생성되는 `report.md`, `report.html`, 복수 데이터셋의 `index.html`에도 적용한다. 도움말, 진행 상태, 진단 설명, 오류, 안내, 표 제목·접근성 레이블까지 포함한다. 저장소가 소유한 예제 실행 경로에서 직접 출력하는 안내도 같은 범위다.

명령어·옵션·환경 변수 이름, 데이터셋/컴포넌트 ID, 파일 경로, 지표 이름, 상태 코드, JSON/JSONL/CSV의 구조와 의미는 번역하지 않는다. 진단 JSON의 `message`/`remedy`와 저장된 오류 원문은 기계 기록으로서 영어로 유지한다. Git·Docker·uv·외부 Agent·팀 플러그인 등 외부 실행 결과와 자유 형식의 로그는 원문 그대로 둔다. 모델에 전달되는 프롬프트나 평가 데이터도 변경하지 않는다.

## 선택 방식과 호환성

- `AGENT_OPT_LANG`가 없거나 빈 문자열이면 `ko`; `ko`와 `en`만 지원한다. OS `LANG` 값과 무관하다. `--lang` 옵션이나 영구 설정은 추가하지 않는다.
- `AGENT_OPT_LANG=en make help`, `AGENT_OPT_LANG=en make doctor ARGS="--core"`, `AGENT_OPT_LANG=en agent-opt tui` 등 기존 명령에 동일한 규칙을 적용한다. 셸 시작 단계는 Python 설치 전에도 언어를 판단하고, 잘못된 값은 설치·실행에 앞서 명확한 오류로 종료한다.
- 실행 시작 때 결정된 언어 코드를 `summary.json`의 선택적 `report_language` 필드에 기록한다. `run-session`의 각 실행도 같은 규칙을 따르며 세션 요약과 인덱스에 적용한다. 추가 필드의 이름과 `ko`/`en` 값은 언어와 무관하게 고정한다.
- 보고서 생성은 실행에 기록된 언어를 사용한다. `agent-opt report <run-dir> --html` 재생성 시 `AGENT_OPT_LANG`에 명시적으로 `ko` 또는 `en`을 지정하면 **이번 재생성에만** 우선 적용하고 기록된 실행 언어는 바꾸지 않는다. 빈 값은 재생성 언어 덮어쓰기로 간주하지 않는다. 언어 기록이 없는 기존 실행은 이미 생성된 `report.html`의 `<html lang="ko|en">`을 확인하여 기존 언어를 유지하고, 파일이 없거나 알 수 없으면 영어를 사용한다. 기존 실행도 명시적인 환경 변수로 한국어 재생성이 가능하다.

## 구성과 데이터 흐름

1. Python에 작은 공통 문구 목록과 언어 선택 함수를 둔다. 한국어·영어 한 쌍의 고정 문구를 키로 조회하고 변수(경로, 수치, ID 등)는 표시 직전에 안전하게 삽입한다. 기존 평평한 모듈 구조를 유지하며 별도 번역 프레임워크를 도입하지 않는다.
2. `bootstrap.sh`는 Python 실행 이전에 필요한 자체 도움말·검증·설치 진행 문구만 같은 `AGENT_OPT_LANG` 규칙으로 처리한다. `Makefile`은 현재처럼 명령과 인수를 전달하며 새 파서가 되지 않는다. 이후 `scripts/dev.py`, `scripts/dev_doctor.py`, `scripts/menu.py`와 저장소 소유의 예제 안내는 Python 문구 목록을 공유한다.
3. `src/agent_optimizer/cli.py`의 Typer 도움말·일반 출력, `setup_wizard.py`의 질문, `terminal_report.py`의 진행 레이블은 표시 시 번역한다. `korean_help.py`/`terminal_style.py`의 argparse 기본 도움말과 오류 접두어도 선택한 언어로 바꾼다. 컴포넌트 계약과 실행 이벤트의 스키마는 건드리지 않는다.
4. `results.py`와 `html_report.py`는 동일한 언어 선택을 보고서 작성에 전달한다. `report_model.py`가 만드는 수치·출처·평가 근거는 그대로 유지하고 Markdown/HTML의 제목, 설명, 표, 공백 상태 및 HTML의 `lang`, 탐색·접근성 문구만 번역한다. 메트릭·상태 코드와 JSON 코드 블록은 원래 값을 유지한다. 세션 인덱스에도 동일하게 적용한다.

## 오류와 진단

프로젝트가 정의한 도움말·진단·오류는 번역 가능한 고정 문구를 표시 경계에서 선택한다. 내부 진단 식별자와 저장된 영어 `message`/`remedy`는 유지하고, 사람이 읽는 진단 화면은 식별자에 대응하는 번역 문구를 사용한다. 오류에 프로젝트 문구와 외부 도구의 원문이 함께 있으면 프로젝트 안내만 번역한다. 알 수 없는 외부 실패 상세는 번역이나 단순 문자열 치환 없이 그대로 보존한다. 보고서에 담긴 원본 오류 기록·증거도 변형하지 않으며, 생성된 설명과 알려진 프로젝트 오류의 표시만 현지화한다.

지원하지 않는 언어 값은 한국어로 조용히 대체하지 않는다. 셸 시작 경로 및 Python 직접 실행 모두 사용 가능한 값(`ko`, `en`)을 알려주고 기존 실패 상태로 종료한다. `--json` 출력은 언어와 관계없이 동일한 키·상태 값·영문 진단 문구를 사용하며 색상 제어 문자도 섞지 않는다.

## 확인 기준

- Python/.venv 없이 `make help`와 `bootstrap.sh`의 기본 한국어·영어 선택 및 잘못된 값의 조기 실패를 확인한다.
- 개발 명령과 사용자 CLI/TUI의 도움말·질문·진행·오류·진단에 대해 두 언어의 대표 경로를 검사한다. TTY/비TTY 동작과 기존 명령·옵션을 유지한다.
- 동일 입력의 `--json`/실행 이벤트/CSV에서 기존 키·상태·진단 원문이 언어에 따라 바뀌지 않는지 확인한다.
- 두 언어로 생성한 `report.md`, `report.html`, 세션 `index.html`의 문구·HTML `lang`·이스케이프·링크를 확인한다. 기존 실행의 영어 재생성, 실행 언어 보존, 명시적 덮어쓰기와 이후 재생성 시 원래 언어 복귀도 검증한다.
- 관련 테스트 뒤 전체 테스트와 `make lint`를 실행한다. 최초 개발환경 테스트 실패는 새 워크트리의 `.venv` 부재와 기존 테스트의 상위 모델 환경 변수 상속에 기인했다. 코어 환경은 `make setup ARGS="--core --offline"`으로 준비했다. 다국어 변경과 무관한 모델 환경 변수 테스트 격리는 별도 브랜치에서 검증·수정한다.
