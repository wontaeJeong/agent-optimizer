# 보고서 근거 일관성 개선 설계

## 목적과 범위

기존 `runner.py` → `report_model.py` → `results.py` → `html_report.py`/`report_visualizations.py` 흐름을 유지한다. `summary.json`, `events.jsonl`, 선택 결과와 CLI의 원본 의미는 바꾸지 않는다. 세 파생 출력에서 검증 비교·최종 test·평가 건수·근거 경고가 일치하도록 한다. 다른 그룹이나 split 사이에서 점수를 합산하거나 누락 기록을 재구성하지 않는다.

## 선택한 방식

`report_model.py`에서 한 번만 근거 진단을 만들고 렌더러는 이를 표시한다. 단순 경고 문구만 추가하는 방식은 후처리할 수 없고, `result.json` 등에서 손실된 이벤트를 복구하는 방식은 원본 기록의 출처와 카운트를 혼동하므로 사용하지 않는다. 이미 구현된 구조·시각화는 필요한 표기만 수정한다.

## 근거 진단과 파생 스키마

이벤트 파일이 없거나, 비어 있지 않은 줄이 UTF-8/JSON 객체로 해석되지 않으면 파일 상태와 손상 줄 수를 기록한다. 읽을 수 있는 이벤트는 원래 순서를 유지하고 손상된 줄만 제외한다. 각 그룹에서 `summary.groups[].trial_count`가 정수로 기록되었다면 해당 Agent × Harness의 읽힌 `trial_completed` 건수와 대조한다. `summary.trials_used`는 예약 예산이므로 실제 완료 건수와 차이가 날 때 별도 경고를 기록하되 기록 유실이라고 단정하지 않는다. 과거 실행에서 비교 기준이 아예 없는 값은 `null`로 둔다. 없는 이벤트 파일도 완료 예정 건수가 0이든 아니든 따로 표시한다.

`report.json`의 `report_schema_version`을 2에서 3으로 올리고 최상위에 `evidence`를 추가한다. `evidence`에는 이벤트 파일 존재 여부, 유효/손상 줄 수, 읽힌 완료 이벤트 수, `status`(`consistent`/`warning`/`unknown`)와 코드·그룹·기대/관측 건수가 포함된 `warnings`를 둔다. 경고가 있으면 `warning`, 경고가 없고 그룹의 기록된 `trial_count`와 전부 대조했다면 `consistent`, 대조할 수 없으면 `unknown`으로 표시한다. 해당 기준이 알려지지 않았거나 관측할 수 없는 수치는 `null`을 사용한다. 기존 v2 필드의 이름·값·선택·비교 계산은 유지한다. `summary.json`과 `events.jsonl`의 스키마 및 재생성 CLI는 그대로다. 보고서는 이전 실행의 `report.json`을 입력으로 신뢰하지 않고 저장된 원본에서 다시 만든다. 문서에 v1 원본과 v2/v3 파생 필드의 관계 및 호환성을 명시한다.

## Markdown과 HTML

Markdown은 그룹별 기준→선택 **validation** 표와 선택을 확정한 뒤 기록된 **final test** 표를 분리한다. 각 지표의 방향·우선순위·값·개선 방향과 선택 후보 ID는 공통 보고서 모델에서 읽는다. 단계별 선택·후보의 `changes.diff`·평가/실패 원본은 실제 존재하는 안전한 상대 링크로 연결한다. 파일이나 기록이 없으면 링크를 지어내지 않고 안내한다. 체크포인트와 전체 지표 JSON을 표 셀에 넣지 않고 `report.json`/원본 파일을 참조한다. 비신뢰 텍스트는 HTML 태그와 Markdown 표·링크·강조·제목·코드 펜스 구문을 이스케이프하고 표에서는 길이를 제한한다. 잘린 텍스트의 원본 전체는 `report.json`이나 해당 원본 파일의 상대 링크로 제공한다.

HTML은 요약 근처에 근거 경고를 짧게 표시하고 상세 원본·평가로 연결한다. 기존 독립형 HTML, 색상·좁은 화면·키보드 초점·테이블 국소 스크롤과 안전한 상대 링크를 유지한다. 다중 지표 진행 차트의 점은 첫 지표의 실제 값, 계단선은 **사전식 전체 최고 후보의 첫 지표 값**이라고 명시한다. 사전식 전체 최고 후보가 바뀌어도 첫 지표 값은 같거나 내려갈 수 있으므로 수치상 최고점이라고 표현하지 않는다. 진행 목록에는 목적 지표의 순서·방향과 선택 후보 근거를 계속 보여주고 Optimizer 이름 또는 trial 순서만으로 탐색 관계를 추정하지 않는다.

## 검증

기존 테스트와 최소 데모를 재실행하고 세 파일의 선택 ID, 비교 방향, 그룹별/전체 완료 건수와 근거 경고를 대조한다. 단일/복수 지표, 보조 지표가 승부를 결정하는 동률, minimize, 파일 부재·손상 줄·누락 이벤트·예약/완료 불일치, 실패·부분 완료, 원본 v1 재생성, 복수 그룹을 fixture로 검사한다. Markdown의 `<script>`, 파이프·줄바꿈·백틱·코드 펜스·긴 입력도 검사한다. 독립 HTML을 `file://`로 열고 좁은 화면에서 링크와 넘침을 확인한다. UI 변경 전후 화면을 PR에 포함한다.
