# Team-first MVP focus implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development, with task-scoped and final reviews. Tasks run sequentially; do not dispatch nested agents.

**Goal:** Let team developers prepare core tooling, run API-free contracts, and add independently developed Agents/Optimizers quickly, while deferring advanced orchestration.

**Architecture:** Reuse the existing bootstrap, diagnostic collector, menu and flat core. Add a core-only preparation/diagnostic path and narrow orchestration to independent optimizers seeded from baseline, preserving multiple Agents/Harnesses and file plugins. Retired functionality is documented against a recoverable Git revision, not hidden behind a new feature-flag framework.

**Tech stack:** Existing Python 3.11+ stdlib CLI, uv/frozen dev dependencies, unittest, POSIX bootstrap and Make; no added dependencies.

**Spec:** Approved conversation scope: core onboarding first; preserve multiple team-developed Agents and Optimizers, selectable independently with comparable results; defer complex optimizer chaining and advanced objective selection. User approved subagents, PR and merge. This plan records that scope directly; no additional design subsystem is needed.

## Global Constraints

- Work only in `.worktrees/mvp-focus` on `chore/mvp-focus`, starting from `origin/main` at `9afcabe`.
- Multiple Agents, multiple Harness profiles and multiple independently registered Optimizers remain supported. Do not reject multi-Agent/Harness experiments or add a single-optimizer limit.
- Every MVP optimizer stage starts from baseline independently; train-only optimizer feedback and runner-owned validation/test selection remain intact.
- An independent optimizer's history contains baseline and its own train trials, not another optimizer's proposed-candidate trials. A cached baseline measurement may be shared.
- Keep `contracts.py`, file plugin registration, custom evaluator metrics, candidates/diffs/lineage, source isolation, nullable usage, timeout/error/partial result semantics.
- Existing full `setup` and full `doctor` stay compatible; add `--core`. Menu preparation and diagnostic actions default to core, with an explicit ACE preparation choice.
- Core preparation/doctor must not require or execute Docker/Compose/Buildx, fetch ACE/CVDP/data, build images, run simulations or call real model APIs.
- Preserve proxy/CA bootstrap for downloads and existing full ACE paths. Keep current model/env/secret handling and fixed source/data/driver pins.
- Defer stage chaining/gates, weighted/Pareto objective selection, rerank, installed entry-point discovery and named unimplemented research slots. Do not add an experimental enable flag or new plugin manager.
- Keep meaningful tests for live MVP contracts. Convert retired feature acceptance tests into explicit rejection tests; retain restoration references rather than weakening boundary tests.
- No real model calls, no shared-worktree edits, no pushes/PRs/merges by implementers. Controller handles integration and the rebase-only repository rule.
