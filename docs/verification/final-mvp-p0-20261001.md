## 4. A~E가 공유할 최소 계약

### A. App Home·output·설정·이력

- 신규 작은 `app_paths.py`에 `resolve_app_home(env=None, *, cwd=None) -> Path`를 둔다. nonempty `AGENT_OPT_HOME`을 expanduser 후 절대경로로 해석하고 없으면 `~/.agent-optimizer`; 상대 override는 명시 cwd 또는 호출 시 CWD에 고정한다. 함수는 디렉터리 생성/다운로드를 하지 않는다. 빈 override는 기본값을 사용한다.
- 기본 하위 경로는 `experiments/`, `runs/`, `sessions/`, `assets/`, `cache/`, `logs/`. resolver는 경로만 반환하고 init/prepare/run/serve 등 쓰기 동작이 필요한 경계에서만 검증 후 생성한다. help/catalog/history/정적 doctor/plan은 존재하지 않는 Home을 만들지 않는다.
- `resolve_run_base(spec, output=None) -> Path`: **CLI explicit output > TOML에 명시된 output_dir > App Home/runs**. output은 exact run 경로가 아니라 부모 경로다. 기존 TOML 상대 output은 `_root` 기준 및 `safe_path` 검증을 유지한다. session explicit output도 부모 의미를 유지하고 신규 기본값은 App Home/sessions. 자동 migration/cleanup 없음.
- `project_root`/`_root`는 원본 프로젝트의 등록·플러그인·상대 Agent 입력 기준으로 유지한다. App Home을 원본 프로젝트로 가장하지 않는다. local Agent source는 생성 manifest에 절대경로/provenance로 보존한다.
- 외부 설정의 최소 additive 선언은 **선택적 `config_root`**로 통일한다. 없으면 기존처럼 `_root`; 있으면 명시적인 생성 설정 경계 `_config_root`를 해석하고 `agents`, `harnesses`, `benchmark`만 해당 경계의 상대경로로 검증한다. 플러그인/dependency/기존 `candidate_seed_files`는 project 경계 유지. A는 loader·관련 source/benchmark 소비 지점을 통일하고 F는 `write_experiment`/프리셋 writer를 변경한다. `safe_path`에 절대경로나 `..`를 허용하는 해결은 금지한다. 기존 generated `output_dir="runs"`는 명시 output으로 존중하고, 새 기본 설정은 이 필드를 생략해야 Home 기본값이 적용된다.
- 신규 `history.py`의 `list_history(*, app_home, project_root=None, run_bases=(), limit=10) -> list[dict]`와 `verified_report(row) -> Path`를 CLI/TUI 공통 API로 정한다. Home runs/sessions, 명시한 legacy project runs/dev-live, 요청자가 넘긴 output parent만 조회한다. 전체 사용자 디스크를 검색하지 않는다.
- row 필드: `run_id`, `run_dir`, `created_at`, `status`, `experiment_name`, `session_id`, `report_path`, `diagnostic`; 미수집/없음은 `None`. session index도 안전 검증된 `report_path`로 표현하고 session 식별자를 보존한다. 기존 run ID·내부 산출물 구조 유지, canonical path 중복 제거, symlink/특수 파일 차단, 손상 자료의 안전한 건너뜀/진단, 열람 직전 재검증 유지.
- `summary.json`/`manifest.json`/`events.jsonl`을 정본으로 재사용한다. 필요한 최소 `lifecycle.json`만 additive로 두고 run/session 생성 직후와 종료/실패/중단에 기록한다. 이력은 HTML이 없어도 표시한다. 정적 preflight 거부는 diagnostic이며 생성된 run으로 가장하지 않는다.

### B. 선택 row·모델

- `ChoiceRow`: `id: str`, `kind: str`, `label: str`, `description: str`, `enabled: bool`, `reason: str`. B는 `preset_options`의 tuple을 이 공통 형태로 전환하고 실제 동작은 `id`로 결정한다. 한국어 label·list index를 실행 ID로 쓰지 않는다. `reason`은 미구현/자산 미준비/비호환의 한국어 설명이며 Planned row는 `enabled=False`인 UI metadata다. registry에 가짜 factory를 추가하지 않는다.
- 모델 값 출처는 기존 `environment/default/session/missing` 구분을 재사용한다. 안전한 Endpoint는 평문, API key 입력만 password. credential/query/fragment URL은 `ModelSettings.from_env`와 같은 기준으로 거부하고 오류에서도 값을 누출하지 않는다. 입력 취소·뒤로 가기는 준비/모델 호출 없음.
- native 세 역할은 기본적으로 같은 `AGENT_OPT_MODEL_BASE_URL`, `AGENT_OPT_MODEL_ID`, `AGENT_OPT_MODEL_API_KEY`를 소비한다. 기존 `AGENT_OPT_MODEL` provider selector는 coding 프로필용으로 보존하고 native 필수값으로 요구하지 않는다. 역할별 모델 override가 필요하면 C의 예제 metadata에 모델 이름만 두며 endpoint/key는 새 전역 provider 계약으로 늘리지 않는다.
- Agent native 역할 요청과 Optimizer `models.complete` 요청은 별도 사용량/역할로 표시한다. `baseline/file_variants`에 Optimizer API를 요구하지 않는다. native Agent 자체에는 실제 모델 설정이 필요하다. 키는 세션 메모리/환경으로만 전달한다.

### C→D/F. Native 실행 자료·사용량·optional report

- 예제 소유 `native_adapter.py`/`native_bridge.py` 및 별도 native source/profile을 추가한다. adapter의 공개 실행 입력/출력은 **기존 `HarnessAdapter.run(RunRequest) -> ExecutionResult`**다. 최종 평가는 기존 `Evaluator.evaluate(Task, output_dir, timeout_seconds) -> Evaluation`로 검증한다. `RunRequest`에 private row를 새로 넣지 않는다.
- 코어 `ExecutionResult.metrics`는 숫자 또는 `None`이므로 중첩 native JSON을 metrics에 넣지 않는다. C는 `request.logs/native-execution.json`에 version 1 sidecar를 기록한다. 필드: `schema_version`, `execution_mode="native"`, `source_revision`, `source_hash`, `profile`, `task_id`, `candidate_hash`, `status`, `attempts`, `requests`, `generated_files`, `evidence_paths`, `native_wall_time_seconds`, `usage_status`.
- `attempts`에는 실제 `attempt`, `iteration`, `status`, `generated_files`·hash·근거 상대경로를 기록한다. `requests`에는 `request_id`, `role`(generator/reflector/coordinator), `model`, `status`, `duration_seconds`, `input_tokens`, `output_tokens`, `cost_usd`; 없는 값은 null. 식별자는 해당 trial 안에서 유일하며 재시도별 식별을 보존해 중복 합산하지 않는다. prompt·RTL 본문·private evaluator 내용·키·credential URL을 metadata/events에 복제하지 않는다.
- F는 `GroupRunner.trial`의 `result.json`/`trial_completed` 작성 지점에서 검증된 sidecar의 안전한 요약을 optional `native_execution` 필드로 연결한다. A의 runner 경로 작업 이후 F가 producer를 소유한다. 기존 `execution`·`artifacts`·metric 이름을 재작성하지 않는다.
- D는 `build_report`가 `trial_completed.native_execution`을 정규화한 optional 최상위 `native_execution` 목록을 v3에 추가하는 방식으로 통일한다. 없으면 기존 출력대로 처리하고 renderer는 동일 normalized 값만 사용한다. raw events/summary는 renderer 편의를 위해 변경하지 않는다. C는 renderer를 수정하지 않는다.
- 내부 native 평가와 outer trusted 최종 평가의 목적·횟수·wall time을 구분한다. 모델 요청 시간 합계는 native/outer wall time이 아니며 가격 근거 없는 비용은 null. usage 전체 수집이 증명되지 않으면 `usage_status="partial"` 또는 `"unreported"`; 수집 없는 값은 0이 아니다. 서버 공개 asset에 raw evidence/private 자료는 포함하지 않는다.

### E→F. 보고서 서버

- 표준 라이브러리 `report_server.py`의 `start_report_server(report_path: Path, *, port: int = 0) -> ReportServerHandle`로 통일한다. handle은 실제 `url: str` 및 idempotent `close() -> None`을 제공한다. import만으로 서버를 시작하지 않는다. 기본 bind는 고정 `127.0.0.1`, port는 0 또는 1~65535, public bind 옵션 없음.
- 보고서 파일 한 개와 명시 승인한 안전 asset만 제공한다. run root 전체 static 노출/dir listing 없음. 디코딩 후 traversal, symlink, 특수 파일, 미허용 파일 거부. `.env*`, credential, source/candidate, private evaluation, log/manifest/raw evidence는 자동 공개하지 않는다. 현재 HTML은 자체 포함이므로 초기 allowlist는 HTML만으로 충분하다.
- F가 `cli.report_command/_dispatch`에 `--serve`, `--no-open`, `--port`와 TUI Result/History 열람 action을 연결한다. stdout JSON과 충돌하는 `--json --serve` 등 조합은 서버/mkdir/browser 부작용 전에 거부한다. 기존 report 명령에는 `--json`이 없으므로 F가 추가 여부와 기존 단일 JSON 출력을 함께 정리한다.
- browser 실행은 F 소유이며 실패 시 실제 URL을 안내한다. CLI Ctrl-C/예외, TUI 종료/보고서 교체 시 `finally`에서 close한다. 열람 직전 A의 `verified_report`를 사용하고 E도 자신의 allowlist 경계를 검증한다.

실제 upstream 경로는 `ace_cvdp_native_runner.py` → `ace_cvdp_native.cli.main` → `run_datapoint` → spawn `attempt_worker_main` → `run_attempt`. `run_attempt`는 CVDP processor prepare/generation→실제 평가→pass/infra 판정→coordinator/reflection/fresh-start→다음 iteration을 소유한다. 기본 CLI는 attempts 5, datapoint workers 4, max iterations 30이므로 그대로 MVP trial 기본값으로 복사하지 않는다. C는 제한된 단일 과제·attempt와 outer 예산을 명시하고 취소/child cleanup을 검증한다.

**C가 먼저 해결할 세 연결 차이:**

1. Generator: `AceIterationModel.prompt` → `run_role_call` → 자식 `llm_call.py` → `call_with_retries`; `ACE_RTL_LLM_SCRIPT`의 stdin JSON→stdout content/choices adapter hook이 실제 존재한다. 반면 `FocusedDebugger`/`FreshStartCoordinator`는 `utils.llm_client.LLMClient._setup_client` → 직접 `LLMBackend` → `.prompt`로 간다. 해당 `_setup_client`에는 script hook 분기가 없고 backend는 기본 NVIDIA 모델/key만 허용한다. **Generator script 설정만으로 세 역할이 제품 endpoint를 사용한다고 주장할 수 없다.** C의 trusted 예제 bridge가 두 호출 경로를 기존 `ModelSettings/complete`로 연결해야 한다. 역할 응답 파일의 존재만으로 API 요청을 셋씩 계산하지 않는다.
2. Private 경계: `run_attempt`는 `build_evaluator_error_report`로 평가 로그를 읽고 `build_reflector_harness_context`는 비-RTL target에 `src/.env`, `*.py` 등 harness 내용을 읽는다. coordinator의 `_build_immutable_harness_context`도 checker를 읽는 경로가 있다. upstream loop를 보존하되 trusted 예제 feedback/context 경계에서 공개 입력·허용한 실패 요약만 모델로 전달하도록 연결하고 sentinel fixture로 검사한다. 원본 upstream/private 파일은 수정하지 않으며 trusted 평가 bridge는 editable 밖이다.
3. 활성 surface: 현재 coding용 `role-guidance.md`와 `agent_opt_scaffold.py`를 이름만 native editable로 가져오지 않는다. C는 실제 generator prompt에 읽히는 텍스트와 native orchestration에서 실행되는 Python surface를 제공하고 GEPA/Meta-Harness 후보 A/B의 실제 request/import 차이를 증명한다. 후보 실행은 `request.agent_dir`의 snapshot을 사용한다. upstream CLI `main`은 dataset/output/CVDP repo를 workspace 안으로 제한하므로 원본 private repo를 단순 symlink하거나 전체 private row를 Agent workspace에 넣는 방식으로 우회하지 않는다. 예제 trusted bridge에서 `run_attempt` 연결과 평가 경계를 조정한다.

네 CID(`cid002`, `cid004`, `cid007`, `cid016`)는 C가 고정 실제 row별 `input/output.context`, target 수·형식, 공개/평가 자료, OSS 툴, result 구조를 대조한다. P0는 현재 importer의 `cid003`/RTL-only 차이를 확인했으며 네 CID 지원을 선언하지 않았다. 단순 필터 해제·단일 target 가정·상용 EDA 어댑터 추가 없이 지원/구체적 차단을 표와 fixture로 인계한다. 설치형 native 자산 배포에 필요한 first-party pin/소비 파일 변경은 C→F의 명시적 인계 대상이며 문서 갱신만으로 SHA를 자동 갱신하지 않는다.

**작업 격리 게이트:** P0만 현재 지정 워크트리에서 확인했다. A~E 워크트리 생성/환경 검증은 이 P0에서 수행하지 않았으므로 완료라고 주장하지 않는다. 총괄은 담당별 독립 워크트리와 고유 임시 `<임시루트>/final-mvp-{A|B|C|D|E}/home`, `output`, `cache`를 지정하고 `AGENT_OPT_HOME`, `XDG_CACHE_HOME`, 명시 output/cache 인수가 해당 담당 경로인지 시작 시 확인한다. 공유 `.venv`는 실행만 허용하며 setup/sync/사용자 Home·개인 이력 읽기/정리는 금지한다.

**게이트 순서:** P0 → A/B/C/D/E 각각 전용 테스트+새 계약 인계 → F 통합 → G 진단/공유 파일 → H 문서 → I 수용검증. full unit baseline은 현재 환경 오류 때문에 녹색이 아니다. 이를 신규 구현 실패와 분리해 비교하고 G에서 해소한다. 신규 기능의 fixture/mock/계약 검증은 바로 시작 가능하며 실모델/native 실도구 성공은 별도 승인된 실행 근거가 있을 때만 기록한다.
