### 2. 같은 그룹의 validation 비교

baseline과 선택된 후보의 **validation 집계**는 **동일 Agent × Harness 그룹 안에서만** 비교합니다. 아래 발췌는 `rtl-solo/fixture`의 기준 검증 `solve_rate` 0.000 → 선택 검증 1.000입니다. 테스트 성능이나 실제 모델 성능을 뜻하지 않습니다.

### 3. 선택·실패·사용량

Optimizer는 **train** 결과만 수정 근거로 사용하고 **validation** 수치로 후보를 고릅니다. 선택을 고정한 뒤에만 설정된 최종 **test**를 실행합니다. 후보 변경·실패 원인·재현 정보도 보고서에서 살피세요. 미수집 지표는 `null`, 관측된 partial 사용량은 전체 Agent 사용량이 아닙니다.

## 같은 실행 폴더의 파일

| 파일 | 구분 | 확인할 내용 |
|---|---|---|
| `summary.json` | 실행 기록 | 상태, 그룹별 기준/선택/최종 테스트, 예약 `trials_used`; `agent-opt report RUN`의 출력 |
| `events.jsonl`, `manifest.json` | 실행 기록 | 시간순 이벤트·평가/선택 근거, 설정·소스·출처 |
| `candidates/*/changes.diff` | 실행 기록 | 후보의 허용 파일 변경 |
| `report.html` | 파생 보고서 | 브라우저에서 여는 독립형 그룹 비교·추이·과제·실패 화면 |
| `report.md` | 파생 보고서 | 같은 보고서 모델을 텍스트로 공유·검토 |
| `report.json` | 파생 보고서 | 원본 요약·이벤트로 정규화한 시각화/후처리용 스키마 v2; 원본 선택 근거의 대체물이 아님 |

이미 저장된 실행의 보고서 파일을 다시 만들 때만 `.venv/bin/agent-opt report "runs/<run-id>" --html`을 사용합니다. `<run-id>`를 **출력된 실제 값으로 바꾸세요.** 이 명령은 채점을 다시 하지 않습니다.

:::caution[합성 수치 해석]
첫 실행의 fixture 점수는 연결 확인용입니다. 점수가 올라도 실제 모델이나 외부 Agent 성능 향상은 입증되지 않습니다. 실환경 결과는 선택한 Agent·데이터셋·모델·평가기·예산과 실행 근거를 함께 기록하세요.
:::
