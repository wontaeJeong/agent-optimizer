### 3. 선택·실패·사용량

Optimizer는 **train** 결과만 수정 근거로 사용하고 **validation** 수치로 후보를 고릅니다. 선택을 고정한 뒤에만 설정된 최종 **test**를 실행합니다. 후보 변경·실패 원인·재현 정보도 보고서에서 살피세요. 미수집 지표는 `null`, 관측된 partial 사용량은 전체 Agent 사용량이 아닙니다.

## 같은 실행 폴더의 파일

| 파일 | 구분 | 확인할 내용 |
|---|---|---|
| `summary.json` | 실행 기록 | 상태, 그룹별 기준/선택/최종 테스트, 예약 `trials_used`; `agent-opt report RUN`의 출력 |
| `events.jsonl`, `manifest.json` | 실행 기록 | 시간순 이벤트·평가/선택 근거, 설정·소스·출처 |
| `candidates/*/changes.diff` | 실행 기록 | 후보의 허용 파일 변경 |
| `report.html` | 파생 보고서 | 브라우저에서 여는 독립형 그룹 비교·추이·과제·실패 화면 |
| `report.md` | 파생 보고서 | 같은 보고서 모델을 텍스트로 공유·검토 |
| `report.json` | 파생 보고서 | 원본 요약·이벤트로 정규화한 시각화/후처리용 스키마 v3; 원본 선택 근거의 대체물이 아님 |

이미 저장된 실행의 보고서 파일을 다시 만들 때만 `.venv/bin/agent-opt report "runs/<run-id>" --html`을 사용합니다. `<run-id>`를 **출력된 실제 값으로 바꾸세요.** 이 명령은 채점을 다시 하지 않습니다.

:::caution[합성 수치 해석]
첫 실행의 fixture 점수는 연결 확인용입니다. 점수가 올라도 실제 모델이나 외부 Agent 성능 향상은 입증되지 않습니다. 실환경 결과는 선택한 Agent·데이터셋·모델·평가기·예산과 실행 근거를 함께 기록하세요.
:::

## History와 loopback HTML 열람

TUI Home의 실행 이력은 Home·명시 legacy project·선택한 기존 실험의 explicit output **부모**를 읽기 전용으로 조회합니다. 성공/실패/중단·report 없음·session 및 실제 child도 보여줍니다. HTML 없음은 실행 없음이 아닙니다. 종료 근거 없는 running은 stale, 불충분한 기록은 unknown입니다. 조회로 Home/모델/평가/서버를 만들지 않고 열람 action에서 경로/inode를 재검증합니다.

```bash
# 설명용 값은 run JSON의 실제 run_dir로 교체:
RUN='/실제/run/출력/run_dir'
.venv/bin/agent-opt report "$RUN" --json
.venv/bin/agent-opt report "$RUN" --html
.venv/bin/agent-opt report "$RUN" --serve --no-open --port 0
```

**JSON/MD/HTML은 같은 normalized report v3**입니다. stage별 algorithm trail은 기록된 이벤트/검토 회차/frontier만 사용하고 frozen selection을 바꾸지 않습니다. `--html`은 원본 summary/events로 재생성할 뿐 후보 재선택·모델/평가 실행을 하지 않습니다. 누락/손상/불일치·invalid native는 evidence warning, 미수집은 null, partial은 전체가 아닙니다. native attempt/iteration·역할별 실제 request·native wall time/요청 duration·inner 횟수와 **outer trusted 평가**를 합쳐 같은 지표로 쓰지 않습니다. 손상 sidecar는 optional native만 제외하며 outer 결과는 유지합니다.

`--serve`는 **127.0.0.1의 선택 HTML 한 파일만** 제공합니다. JSON/MD/summary/events/log/candidate/diff/private/native raw와 session child 링크는 allowlist 밖(404)입니다. 실제 child 보고서는 별도로 선택합니다. `--html --serve`는 재생성 후 새 handle로 시작합니다. 기본은 브라우저 요청, `--no-open`은 생략, `--port 0`은 자동 포트입니다. Ctrl+C=130이며 자원을 정리합니다. 명시 포트 충돌은 오류 code/errno·retry를 주고 자동 fallback하지 않습니다. 브라우저 실패에는 URL을 남기며 run 성적을 바꾸지 않습니다. SSH는 서버가 살아 있는 동안 표시 포트로 포워딩하고 127.0.0.1 URL을 엽니다.

`--json/--csv`와 serve, serve 없는 `--no-open/--port` 등 충돌은 부작용 전에 종료 2입니다. `--serve` URL/안내는 stderr, JSON 모드는 stdout 단일 문서입니다. 별도 `serve` 명령은 없습니다. native live와 실제 OS 브라우저/SSH 성공은 현재 not_run이며 위 fixture 이미지로 성공을 주장하지 않습니다.
