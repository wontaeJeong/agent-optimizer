# 문서 사이트 가독성·탐색 개선 설계

## 범위와 현상

`website/`의 7개 하위 페이지와 홈, 사이드바, 그림, 스타일을 손본다. 엔진과 실행 보고서 생성 코드는 수정하지 않는다. 공개된 `/concepts/overview/`의 초기 HTML에는 `<pre class="mermaid">flowchart …</pre>`가 있으므로 브라우저 JS가 그린 뒤에야 그림이 나타나며 Pagefind가 원문을 검색한다. `/getting-started/results/`는 1440px의 7-trial 합성 화면을 본문 폭으로 축소하며 첫 실행 페이지는 7-trial 자동 실행과 별도 2-trial 수동 설정을 한 흐름처럼 소개한다. 변경 전 캡처는 별도 임시 증거로 보존한다.

## 경로와 콘텐츠

홈의 세 진입점은 `첫 실행하기` → `결과 읽기`, `내 Agent로 실험하기` → `실험 구성`, `팀 컴포넌트 개발하기` → `컴포넌트 연결`이다. 각 카드에 선행 조건과 다음 페이지를 적는다. 사이드바는 `시작하기`(첫 실행·결과), `실험하기`(실험 구성·동작 원리), `팀 컴포넌트 개발`(컴포넌트 연결·구조와 경계·검증 순서)로 축소한다. 기존 7개 URL과 공개 앵커를 유지하고 각 페이지의 다음 경로를 명시한다.

기본 첫 실행은 저장소 루트에서 `make setup-core`가 만드는 7-trial 합성 데모다. Git·make·Mac/Linux 및 설치 시 네트워크 요구 → 그대로 실행할 명령 → 진단·실행 결과의 확인 필드(`status`, `trials_used`, `run_dir`, `synthetic`) → `report.html` 열기 순으로 제시한다. `make setup-core`의 자동 실행과 나중에 실행하는 별도 `run`의 보고서 경로를 혼동하지 않는다. `guide-fixture`의 2-trial 직접 작성은 선택 절, 모델·Docker·인증과 실환경 평가가 필요한 ACE/CVDP도 분리된 선택 절 및 실험 구성으로 안내한다. 정적 `doctor --plan`의 `ready`와 실제 외부 평가 성공을 구분한다.

긴 문서는 전제 조건, 절차, 결과 확인, 경계/주의점으로 구획한다. 팀 경로는 README 빠른 시작 → `experiments/README.md` 템플릿 → `docs/adding-components.md`와 `contracts.py` → `registry.py` → 검증 순서로 연결한다. GitHub의 고정 `main` 파일 링크를 사용하고, 템플릿 파일이 준비되지 않은 의사코드는 실행 예제와 별도로 명시한다. 페이지별 description을 넣는다.

## 그림과 결과

Mermaid 클라이언트 변환을 제거한다. 네 개 개념 도표와 개발자 페이지의 추가 도표는 빌드 결과에 SVG만 나타나도록 정적 SVG 자산으로 유지하고, 실제 페이지의 접근 가능한 대체 설명과 SVG 내부 제목·설명을 함께 제공한다. 관계가 교차하는 구조도는 데이터 준비/실행·채점/후보 제안·기록의 흐름을 구분하고, 긴 실험 단계는 준비/실행/선택·보고로 구획하되 train → validation → 선택 고정 → 선택적 test 경계는 유지한다. 밝음·어두움에서 읽히는 전경/배경 대비를 확보하고, SVG 주변 prose는 색에 의존하지 않는다. 작은 화면에서는 그림 컨테이너만 가로 이동하게 하고 안내를 적는다. Pagefind는 설명 문단을 색인하지만 원본 Mermaid 문법은 색인하지 않게 한다.

결과 페이지는 7-trial 합성 보고서라고 명시한 기존 이미지에서 상태·예산과 validation 비교 영역을 잘라 크게 보여 주고, 원본 해상도 보기 링크를 제공한다. 2-trial `guide-fixture`와는 다른 실행임을 이미지와 캡션에서 알린다. 저장된 원본 `summary.json`/`events.jsonl`/`manifest.json`과 파생 `report.html`/`report.md`/`report.json`의 용도를 짧은 표로 구별한다. 실행 증거가 아닌 합성 fixture 수치의 의미를 설명한다.

## 스타일·검증

Starlight 검색·메뉴·목차·테마·코드 복사는 그대로 사용하고, 본문 최대 폭과 글자·문단 간격, 카드 제목 줄바꿈, 표·코드 블록의 독립적인 가로 스크롤만 소폭 조정한다. 360/390/768/1440px 및 두 테마에서 경로 탐색, 메뉴, 그림, 표, 복사, 이미지 원본 보기, 키보드 동작을 확인한다. `evaluator`, `평가기`, `첫 실행` 검색과 네 도표 초기 로딩·색인 원문 부재를 확인한다. `website/`의 `npm ci` 및 `npm run build`(기존 내부 URL/앵커 검사 포함)를 실행하고, UI 변경 전후 캡처·재현 절차·원인과 선택한 렌더링 방식을 PR에 남긴다.
